# DailyCalendar 4.0.0

## 바뀐 점

- 학사정보를 등록할 때 지역 지도와 필터, 대학 교표를 볼 수 있습니다. 앱이 지역에 맞는 분교를 자동으로 고릅니다.
- 학사일정을 연동하는 대학을 늘렸습니다. 학교 시간표 검색은 검증을 마친 10개 대학에서만 계속 제공합니다.
- 시간표에서 교필과 교선 표시, 학과 선택, 공식 전공제도 기준의 소속 분류를 고쳤습니다.
- LMS 자동 로그인을 선택해서 켤 수 있습니다. 로그인 정보는 기기마다 보안 저장소에만 저장하고 다른 기기로 보내지 않습니다. 일정은 Google 계정으로 동기화합니다.
- LMS 퀴즈 완료 상태와 직접 완료 처리한 일정이 더 잘 유지됩니다. 같은 내용을 반복해서 조회하는 횟수도 줄였습니다.
- 완료 취소선 색을 다크 모드에서는 흰색, 밝은 모드에서는 검정색으로 맞췄습니다.
- 빠른 보기와 시간표 사이 전환, 대학 목록의 마우스 스크롤, 지역 전환 애니메이션을 다듬었습니다. 실제 프레임률은 기기, 디스플레이, 실행 상태에 따라 다릅니다.
- 앱을 시작할 때 실행하는 동기화의 상태 처리와 계측을 고쳤습니다. 동기화 중에도 개인 분류와 완료 상태가 유지됩니다.

## 지원하는 대학

학교 시간표 검색을 지원하는 대학은 상명대학교, 단국대학교, 아주대학교, 중앙대학교, 이화여자대학교, 홍익대학교, 인하대학교, 부산대학교, 세종대학교, 서울대학교입니다.

작업을 마치지 않은 대학은 학교 시간표 검색을 잠정 미지원으로 표시합니다. 이 대학에서도 기존 학사일정, 저장한 시간표, 직접 수업 추가는 그대로 쓸 수 있습니다. 대학 전체의 시간표 지원을 마쳤다는 뜻은 아닙니다. 남은 원자료와 분류 작업, 단과대 선택 구조를 통합해 달라는 요구는 [이슈 #92](https://github.com/littlebit0/DailyCalendar/issues/92)에 적어 두었습니다. 단과대가 주관하는 항목을 같은 단과대 안으로 묶는 새 UI는 이 버전에 넣지 않았습니다.

LMS 연결은 현재 지원하는 학교에서만 쓸 수 있습니다. 자동 로그인은 설정한 기기에서만 동작합니다. 학교 정책에 따라 한 기기에서 로그인하면 다른 기기의 LMS 세션이 로그아웃될 수 있습니다.

## 배포 파일

Drive v2와 DB 스키마 9는 바뀌지 않았습니다. GitHub 설치 파일과 Apple App Store 제출용 서명 파일은 서로 다른 파일입니다. Transporter 파일을 만들었다고 해서 Apple에 업로드했거나 심사를 제출했거나 스토어에 공개했다는 뜻은 아닙니다.

## 검증 결과

제품 lib/test 정적 분석을 통과했습니다. 전체 Dart 검사는 처음에 1,982개 통과, 1개 건너뜀, 29개 실패였습니다. 이 중 오래된 취소선/UI 기대값과 지역 제공자 테스트 설정 때문에 난 11개 실패는 고친 뒤 해당 범위를 다시 검사해 통과했습니다. 보류 중인 원자료·스냅샷 검사 18건은 이슈 #92에 남아 있으므로 전체 검사를 통과한 것은 아닙니다. Apple 쿠키, 비밀번호 입력, Siri 정책 검사와 iOS/macOS Release 아카이브, App Store 배포 서명 검증을 통과했습니다. GitHub Actions에서 Windows, Android, iOS, macOS, Linux ARM64 배포 빌드가 통과했습니다. 사용자 결정에 따라 Linux AMD64는 3.6.0으로 둡니다. AMD64 작업은 전체 테스트를 통과해야 하는데 보류 원자료 실패가 있어 출판 대상에서 뺐고, 자동 APT 채널도 기존 3.6.0을 그대로 제공합니다. 모든 GitHub workflow가 통과했다는 뜻은 아닙니다. 보류 대학의 원자료 검사와 실계정·실기기 전체 동작 확인은 마치지 않았습니다.

원격 전체 CI 결과는 1,508개 통과, 247개 실패, 33개 건너뜀입니다. 실패 중 243건은 Git에서 제외한 `work/` 원자료/스냅샷에 의존해 파일을 찾지 못한 경우이고, 나머지 4건은 보류 대학의 기대값 차이입니다. 로컬 검사 결과와 원격 재현성은 구분해서 보고, 인계 이슈 #92에서 함께 처리합니다. Android/Windows Debug 빌드는 따로 통과했습니다.
