# Priority 5–10: credential preservation, analytics withdrawal, notification reset

User scope: #207, #208, #201, #205, #140, #142. Implementation and verification only. No installation, launch, commit/push, release, issue closure or university work.

## Changes

- **#207 Android**: vendor flutter_secure_storage 10.3.1 with original license. Both Dart Android option constructors default resetOnError to false. The Daily native configuration refuses automatic destructive resets even if an older caller supplies true. Native read/readAll and plugin/migration fallback errors propagate; explicit delete/deleteAll remains available.
- **#208 Android**: the app's ordinary RSA/CBC → RSA-OAEP/GCM migration retains existing keys and ciphertext. New wrapped keys require a successful synchronous commit. Every new ciphertext is encrypted and round-trip checked before publication. Ciphertext and authoritative algorithm markers are committed to the same data preferences file. On commit failure, restore the original preference values/cache and report failure; keep old keys even if rollback fails. Restart reads the markers beside the ciphertext before legacy separate configuration. Constructor no longer prematurely publishes new algorithms. Namespaces stay isolated. The non-biometric backup flag also routes through this atomic path. Unused key-only algorithm transitions sharing one wrapped-key slot fail without deleting originals; custom biometric/Secure Enclave migration behavior is not claimed to be newly supported.
- **#201 Apple**: vendor flutter_secure_storage_darwin 0.3.2. Standard Keychain writes update first; only errSecItemNotFound permits add. A duplicate-add race retries update once. Interaction, authentication and decode errors return without delete-and-recreate. Original service/access-group/accessibility options are retained.
- **#205 Windows**: preserve encrypted file on DPAPI/decode/JSON/shape failure. File read errors propagate except file/path-not-found. Invalid object entries reject the whole document instead of silently dropping individual credentials. Parse errors do not include decrypted payloads in diagnostics. Existing explicit delete behavior and bounded save retries remain.
- **#140 Analytics**: withdrawal immediately blocks new collection/transmission and invalidates late asynchronous work. Checked, read-back-verified preferences plus a separate secure-storage consent journal protect partial writes. Unknown/unreadable journal fails closed; legacy preference remains readable when no journal exists. Both stores are attempted on withdrawal, failures are reported, repeated OFF retries persist again, and queued data removal checks completion. Consent/queue writes are serialized; a late response cannot resurrect a deleted queue. Settings has retry/error UI, onboarding does not claim failed consent-completion writes succeeded. Existing analytics ON/OFF choice is preserved; no forced consent or advertising change.
- **#142 Notifications**: persist a minimal cleanup journal (event IDs, reminder offsets, D-day offsets, briefing flag) before reset erases the event DB. If journal storage fails, reset fails before deleting account data. Individual cancellation failures do not skip subsequent events/briefing; retain failures for startup/later scheduling retry. OS mutations remain serialized even when the caller times out. Old queued schedules are invalidated, and new schedules wait until old cleanup completes. Reset cleanup removes pending and delivered OS notifications using existing cancel APIs; normal rescheduling still uses existing pending-only behavior. The journal survives settings reset and contains no titles, dates, account credentials or bodies. Pending cleanup is explicitly reported to the user.

## Corrections and limits

- First Android native compile exposed an overly broad replacement of an inline configuration getter. Restored the untouched getters and changed only the intended method; native suite then passed.
- Initial manual CocoaPods invocation used --project-directory from the repo root, while Flutter's helper checks package paths relative to cwd. It installed duplicate SwiftPM pods. Re-running from the ios directory restored the original Podfile.lock and the final iOS build passed. No CocoaPods dependency upgrades retained.
- Automatic approval rejected deleting the newly copied upstream Dart tests. Tests were retained, their dev dependencies resolved, and all 93 ran successfully. No test coverage was hidden or skipped to obtain a pass.
- **If both secure storage and preferences reject all writes**, a process cannot persist a new withdrawal intention across power loss. Current-session collection is stopped and the UI reports failure/retry before exit. A successful write to either store preserves OFF on restart. Do not claim the simultaneous-total-write-failure case is durably solved.
- **Windows native DPAPI/device acceptance, real Android Keystore failure/process-kill tests, actual Apple Keychain failure and live OS notification-center cleanup were not performed.** Tests are fault-injected logic/real file preservation plus available native compilation. No remote/full CI claim. Existing private app data/accounts were not used or changed.
- Licensing retained. Local dependency overrides are required when carrying these patches forward; do not replace them with unpatched upstream versions during dependency upgrades.
