## Changes

- **#113 OAuth session races:** desktop OAuth (including its Apple-platform path) invalidates prior operations when a new sign-in, account selection, cancellation or logout begins. Code exchange, identity lookup, refresh and secure-store publication check the originating generation. A refresh captures its own account and token, and concurrent requests in the same generation share one refresh. Active sign-in blocks old-account authorization. Short serialized storage operations use one secure JSON session entry, with readback and rollback on unverified/canceled writes; network and browser waits remain outside that queue. A logout tombstone prevents undeleted legacy keys from restoring an old session. Existing five-key sessions remain readable. Android SDK authentication behavior is retained.
- **#131 interrupted migration:** publication no longer renames/deletes the original database or its WAL/SHM. The migrated event and deletion schemas/rows/indexes/triggers and schema version are published in one transaction on the original SQLite connection. Old `.before-todo-replace` files are recovered only when the primary is absent and the candidate is valid/unambiguous. Conflicting candidates, sidecar ambiguity, unreadable originals or an orphan working file block startup while preserving files; they never silently initialize an empty database.
- **#132 concurrent migration writers:** after cloud work, `BEGIN IMMEDIATE` reserves the original writer slot; local versions are reread under that lock before conflict resolution and snapshot creation. The lock spans working-copy repair/validation and publication. Existing connections keep their original file/inode and see the committed schema. Independent writes cannot silently succeed into a discarded file: they wait or receive SQLite busy. Existing Siri code already uses a busy timeout and checks SQLite write results; it was not changed. Cloud backup happens after commit/release.
- **#172 lock persistence:** enabled/method/biometrics are committed together in `appLockConfiguration.v1`; false returns, exceptions and failed readback propagate after refreshing the plugin cache. Legacy settings remain readable, malformed new settings fail closed, reset removes the new key. PIN deletion runs only after successful settings save. Failed/canceled settings updates are reported in the UI and retain PIN credentials. Windows keeps its ordinary control animation behavior but does not optimistically display unpersisted lock changes. The iOS wallpaper settings view reads the new configuration, with legacy fallback and conservative malformed-data behavior.
- The already-resolved shared_preferences platform interface is explicitly declared as a dev dependency for controlled false/throw/unwritten persistence tests. No package version upgrade or new runtime dependency.
