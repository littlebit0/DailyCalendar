# 이슈 65 앱 내부 SSO·웹 세션 구현안

2026-09-26. [실계정 확인 결과](ISSUE_65_COSMOS_FEASIBILITY.md)에 따른 구체안입니다.
승인된 계획과 앱 내부 SSO 요구에 따라 구현했으며 Mac에서 실제 가져오기를 확인했습니다.
사용자는 macOS/iOS 수정
금지가 Windows 환경 에이전트에만 적용되는 규칙이라고 정정했으며, AGENTS.md도
수정했습니다. 아래 사용자 흐름은 목표 동작이며, 실제 확인 범위는 다음 상태와
구분합니다.

## 현재 확인 결과와 남은 작업

- 전용 WebView·OS 보안 세션 저장·LMS 메타데이터·소유권 검사·순차 갱신·설정 UI를
  구현했습니다. 사용자가 Mac 앱 안에서 학교 로그인을 직접 완료했고, 저장된
  세션이 수정된 앱 재시작 후 재로그인 없이 복원됨을 확인했습니다.
- 최초 로그인 확인 오류의 원인은 학교가 정상 세션 쿠키를 `Secure` 속성 없이
  발급하는데 Apple 수집 코드가 이 속성을 필수로 요구한 것이었습니다. 이름과
  정확한 학교 호스트·비영구 저장소 검증을 유지하면서 발급 속성 필터를 제거했습니다.
  복원 시 HTTPS·Secure·HttpOnly 제한은 유지합니다. 학교 로그인 성공과 장시간
  유지·인증 만료·모든 SSO/2차 인증 흐름의 검증은 구분합니다.
- `activity_table_missing`은 학교의 정상 빈 과제 알림 형식을 인식하도록 수정했습니다.
  수정된 Mac 앱이 재로그인 없이 저장 세션을 복원하고 현재 연결의 11개 강좌에 대한
  과제·퀴즈 목록 22개를 실제 조회했습니다. **일정 14개 추가, 시간 미지정 0개,
  동기화 `ready`, 오류 없음, 최근 성공 시각 갱신**을 확인했습니다.
- 전체 Flutter 테스트 969개 통과·기존 skip 1개, 정적 분석 문제 없음,
  집중 LMS 테스트 61개와 Apple 쿠키 정책 검사 32개 통과를 확인했습니다.
- Mac, iOS 시뮬레이터, Android debug 빌드가 성공했습니다. Mac 수정본 설치·실제
  가져오기를 확인했고 iPhone 17·iPad Pro 13 시뮬레이터에도 최종 수정본을 설치했습니다.
  보호 대상 파일 해시는 Mac 2개·iPhone 4개·iPad 2개 모두 동일하며 App Store 앱은
  변경하지 않았습니다. iOS 앱 내 인증은 미검증입니다.
  Windows 빌드·실행은 미검증, Android 설치는 스냅샷 문제로 차단된 상태입니다.
  Android 데이터 상태·복구 제한과 최신 증거는 [인수인계](../AGENT_MEMORY.md)에
  기록합니다. 공개 릴리스는 하지 않았습니다.
- 전남대학교 실제 LMS 호환성과 온라인 강의 수강기간·진도의 전체 연결은 미검증입니다.

## 사용자 흐름

1. Daily의 학사정보에서 `LMS 연결`을 누릅니다.
2. 앱 안의 전용 로그인창에서 학교 공식 SSO·2차 인증을 직접 완료합니다.
3. 앱은 로그인 완료와 실제 읽기 권한을 확인한 뒤 과제·퀴즈 일정을 가져옵니다.
4. 연결 후에는 앱 실행·복귀·사용자 새로고침 때 자동 조회합니다. 앱 사용 중에는
   최소 5분 간격으로 최신 상태를 확인하되 요청은 하나씩 수행하고, 진행 중인
   조회를 중복 시작하지 않습니다. 실패 시 대기 시간을 늘립니다.
5. 학교가 인증을 만료시킨 경우 다시 로그인하도록 안내합니다. LMS에서 변경
   알림을 보내는 push 경로는 확인되지 않아 즉시 반영이나 앱 종료 후 상시 동작을
   보장하지 않습니다. 전남대는 별도 실제 호환성 확인 후 확장합니다.

수동 토큰 복사·브라우저 파일 내보내기를 일상 사용 흐름으로 요구하지 않습니다.
시간표·학사일정의 기존 기능과 Google 로그인은 별개로 유지합니다.

## 확인된 데이터 조회 방식

로그인된 같은 출처의 학교 웹 목록 HTML을 사용합니다. 개발용 브라우저 표본 조회에
이어 Mac 앱에서도 현재 연결의 11개 강좌 전체 과제·퀴즈 목록 조회와 가져오기를
확인했습니다. Daily용 API 토큰·반환 경로는 아직 확인되지 않았습니다. API가
존재하지 않는다고 단정하지 않으며, 허용된 구조화 API가 확인되면 우선 사용합니다.

- 첫 구현: 수강 목록, 과제 목록의 마감·제출 상태, 퀴즈 목록의 일정.
- 다음 구현: 강의 수강기간·진도. 미학습 행까지 원본 식별자가 확실히 연결되는
  범위를 검증한 후 적용합니다. 누락된 진도나 `-`를 0% 또는 완료로 추측하지 않습니다.
- 자동 조회는 검증한 목록·보고서 GET 경로만 허용합니다. 과제/퀴즈/영상 상세
  페이지, 응시·재생·제출·읽음 처리·완료 처리 요청은 사용하지 않습니다.
- 학교 화면의 구조가 변경되면 어댑터 수정이 필요합니다. 예상 구조가 맞지 않으면
  조회 실패로 표시하고 마지막 정상 자료를 유지합니다. 정상적인 빈 목록과 파싱
  실패를 구분하며, 일부 범위만 읽었을 때 전체 항목을 삭제하지 않습니다.

## 인증·저장과 플랫폼 작업

- 공통 구현에 `flutter_inappwebview 6.1.5`를 추가했습니다. 공식 문서는 Android, iOS,
  macOS, Windows 지원을 명시합니다. 패키지 지원 표시는 학교별 호환성 증명이
  아닙니다. 현재 실제 인증·저장 세션 복원 증거는 Mac의 상명대학교 연결 범위이며,
  다른 플랫폼의 인증과 취소·만료·2차 인증 변형은 추가 확인이 필요합니다.
- 인증 후 정해진 LMS 출처에서 앱이 시작한 읽기 코드만 실행하고, 필요한 일정
  필드만 반환합니다. 임의 웹페이지가 호출할 수 있는 범용 네이티브 브리지는
  노출하지 않습니다. 학교 로그인 입력값을 수집하거나 비밀번호를 보관하지 않습니다.
- 연결 세션의 기기 보관은 계정·학교별로 분리하고, 유지에 필요한 인증자료는
  OS 보안 저장소를 사용합니다. 앱 내에서 생성한 해당 학교 인증자료만 다루며,
  개발 검증 브라우저의 쿠키를 앱에 복사하지 않습니다. 연결 해제 시 해당 학교의
  세션과 인증자료를 정리하고 Drive·로그에 인증자료를 넣지 않습니다.
- LMS 원본과 개인 메모·분류·알림을 구분합니다. SQLite 스키마 9와 Drive v2의
  저장·복원·삭제 기록에 원본 ID·소유권·상태 보존을 구현하고 회귀 테스트로 확인했습니다.
  테스트 앱 업데이트와 실제 네 플랫폼 간 통합 검증은 다르며, 구버전 앱에는 새
  소유권 보호가 없습니다. 별도 배포 승인과 네 플랫폼의 조정된 산출물 없이
  공유 스키마 릴리스를 게시하지 않습니다.
- 기존 프로젝트는 iOS/macOS 모두 SwiftPM만 사용했습니다. 안정판 플랫폼 패키지
  `flutter_inappwebview_ios 1.1.2`와 `flutter_inappwebview_macos 1.1.2`의 공식
  archive에는 `Package.swift`가 없고 podspec만 있어, 기존 SwiftPM을 유지하면서
  CocoaPods 연동을 추가했습니다. 양쪽 Podfile·프로젝트/워크스페이스 연결·플러그인
  등록과 pod install, Mac·iOS 시뮬레이터 빌드까지 완료했습니다. Mac 수정본과
  iPhone 17·iPad Pro 13 시뮬레이터의 최종 수정본 업데이트를 완료했습니다.
  iOS LMS 채널은 implicit-engine 초기화 콜백에서 등록하고, headless 세션 복원은
  앱이 foreground일 때 시작합니다. 빌드·설치를 학교 인증 검증으로 간주하지 않습니다.
  이 작업은 정정된 AGENTS.md에 따라 현재 Mac에서 수행하는 승인된 LMS 구현 범위입니다.
- 네이티브 변경 범위는 이번 LMS 로그인창의 플러그인 등록·빌드 연결·세션 격리/
  해제에 필요한 최소 설정으로 한정합니다. 기존 iOS Google 인증 채널이나 다른
  기능의 네이티브 오류를 함께 고치지 않습니다. Windows WebView2 필요 여부도
  설치 및 실행 검증에서 확인합니다.

## 승인 경계

2026-09-26 사용자가 플랫폼 규칙 자체를 정정했습니다. Windows 환경에서의
macOS/iOS 구현 금지와 현재 Mac의 네이티브 작업을 구분합니다. 현재 Mac에서는
별도의 플랫폼 예외 승인 없이 승인된 LMS 범위의 플러그인·빌드·세션 작업을 진행합니다.

학교 로그인은 사용자가 직접 수행합니다. 과제 제출·퀴즈 응시·강의 재생·보안키
생성, 계정 변경 및 관련 없는 기능 변경은 승인 범위가 아닙니다.
