# 이슈 65 상명대 코스모스 연동 검증

2026-09-26. [승인된 진행안](ISSUE_65_COSMOS_PLAN.md)의 조사와 후속 구현 검증 기록입니다.
아래 공개 조사·개발용 브라우저 검증은 구현 전 단계의 증거이며, 현재 앱 검증
결과와 구분합니다. **Mac에서 앱 내부 학교 로그인, 저장 세션 복원, 현재 연결의
11개 강좌 전체 과제·퀴즈 목록 조회와 일정 14개 자동 가져오기를 확인했습니다.**

## 현재 구현·검증 상태

- 전용 학교 WebView, 계정·학교별 OS 보안 세션 저장, LMS 소유권·원본 메타데이터,
  목록 파서와 순차 갱신 계층을 구현했습니다. SQLite 스키마 9와 Drive v2에
  LMS 원본과 개인 메모·분류·알림·완료를 구분해 보존합니다.
- 사용자가 Daily Mac 앱의 공식 학교 화면에서 직접 로그인했습니다. 최초
  연결 확인 실패는 학교가 발급한 정상 `MoodleSession`에 `Secure` 속성이 없는데
  Apple 쿠키 수집 코드가 이를 필수로 요구한 문제였습니다. 정확한 학교 호스트와
  전용 비영구 저장소 검증은 유지하고, 발급 시 보안 속성을 인증 여부로 오인하는
  필터를 수정했습니다. 복원은 계속 HTTPS·Secure·HttpOnly로 제한합니다.
- 기존 앱 내부 세션을 보안 저장소에 저장한 뒤 수정된 Mac 앱에서 재로그인 없이
  세션과 비영구 저장소 연결이 복원됨을 확인했습니다. 브라우저 인증자료를
  내보내 앱에 복사한 결과가 아닙니다. 인증 만료·모든 2차 인증 흐름까지 검증한
  것은 아닙니다.
- 실제 목록 수집에서 발생했던 `activity_table_missing`은 학교가 반환하는 정상
  빈 과제 알림 형식을 인식하도록 수정했습니다. 수정된 Mac 앱에서 저장 세션을
  복원한 뒤 11개 강좌의 과제·퀴즈 목록 22개를 실제 조회하고 일정 14개를 추가했습니다.
  시간 미지정 항목은 0개였고 동기화 상태 `ready`, 오류 없음, 최근 성공 시각 갱신을
  확인했습니다. 사용자의 재로그인은 필요하지 않았습니다.
- 전체 Flutter 테스트 969개 통과·기존 skip 1개, 정적 분석 문제 없음,
  집중 LMS 테스트 61개와 Apple 쿠키 정책 검사 32개 통과를 확인했습니다.
- Mac, iOS 시뮬레이터, Android debug 빌드가 성공했습니다. Mac 수정본 설치와
  실제 가져오기를 확인했고, iPhone 17·iPad Pro 13 시뮬레이터에도 최종 수정본을
  설치했습니다. 보호 대상 파일 해시는 Mac 2개·iPhone 4개·iPad 2개 모두 동일하며
  App Store 앱은 변경하지 않았습니다. iOS 앱 내 학교 인증은 미검증입니다.
  Windows 빌드·실행은 미검증이고 Android 설치는 에뮬레이터 스냅샷 문제로
  차단되어 있습니다. Android 현재 앱 데이터 보존 상태도 아직 확인되지 않았으며
  상세 경위·복구 경계는 [현재 인수인계](../AGENT_MEMORY.md)에 기록합니다.
  커밋·푸시·릴리스는 하지 않았습니다.
- 전남대학교 실제 LMS 호환성과 온라인 강의의 전체 수강기간·진도 연결은 아직
  검증하지 않았습니다. 이번 성공 범위는 상명대학교의 과제·퀴즈 일정입니다.

## 구현 전 공개 조사에서 직접 확인한 응답

- `GET https://ecampus.smu.ac.kr/login/index.php`는 `/login.php`로 이동하고
  HTTP 200 로그인 페이지를 반환합니다. 일반 로그인 POST 폼과
  `/exsignon/sso/sso_idp_login.php`를 대상으로 하는 SSO POST 폼이 있습니다.
  폼 제출은 하지 않았습니다. 이 사실만으로 Daily로 돌아오는 인증 경로가
  제공된다고 판단할 수 없습니다.
- Moodle 공식 소스에서 `tool_mobile_get_public_config`는 인증이 필요 없는
  읽기 함수로 선언되어 있습니다. 쿠키·사용자 토큰 없이
  `/lib/ajax/service-nologin.php`에서 이 공개 설정을 한 번 요청했지만,
  상명 서버는 **HTTP 404 / HTML**을 반환했습니다. 이는 이 공개 경로의 실패이며,
  학교의 모든 API가 없거나 인증한 사용자의 웹서비스 접근이 금지되었다는
  증거는 아닙니다. 비공개 경로 탐색이나 로그인 시도는 하지 않았습니다.
- Moodle 일반 문서는 모바일 서비스의 서버 설정과 앱 반환 경로 설정을
  요구합니다. 코스모스 기반이라는 이유만으로 Daily의 접근 권한, 표준 API
  버전, 서버 데이터 필드가 보장되지는 않습니다.
- 조사 당시 상명 공개 테마 JavaScript는 세션을 요구하는 수강 목록 요청과 캘린더
  웹 UI 요청을 포함합니다. 이는 웹 UI 경로의 존재만 확인한 것이며 과제·진도
  데이터 API의 외부 사용 가능성을 입증하지 않습니다. 해당 요청은 실행하지
  않았습니다. 같은 경로에 읽음 처리 등 쓰기 동작도 있어 실제 함수의 부작용을
  확인하기 전에는 호출하지 않습니다.
- 2차 인증은 2024-08-20부터 원격수업 강의실 진입 시 **매일 1회**로 변경됐다는
  공식 공지를 조사 시점에 확인했습니다. 그 이전 ‘로그인 시마다’ 공지만으로 현재
  동작을 단정하지 않습니다. 2025-12-24 로그인 장애 공지는 당일 복구를 명시하므로
  현재 장애의 근거로 사용하지 않습니다.

## 구현 전 개발용 브라우저 검증 — 사용자 로그인 후 읽기 전용 확인

사용자가 공식 화면에서 직접 로그인한 뒤 아래 항목을 읽기 전용으로 확인했습니다.
사용자가 “로그인 후 조회 허용”으로 이 범위를 명시적으로 허용했습니다.
제품은 앱에서 SSO 인증을 시작하고 이후 자동으로 데이터를 갱신해야 한다는
요구도 재확인했습니다. 이 절의 브라우저 확인은 개발용 검증이며 제품 사용 흐름이
아닙니다. 이후 앱 내 로그인 결과는 위 현재 상태에 별도로 기록했습니다.
로그인·2차 인증은 사용자가 공식 화면에서 직접 수행합니다.

| 확인 대상 | 당시 확인한 증거와 한계 | 브라우저 조사 결과 |
| --- | --- | --- |
| 인증 경로 | 로그인된 브라우저의 같은 출처 세션으로 GET 조회 성공. 이 조사 당시 앱 내 인증은 미검증이었으며, Daily용 토큰 반환 경로는 여전히 미확인 | 부분 확인 |
| 수강 목록 | 인증된 대시보드에서 수강 강좌와 `course/view.php?id=...` 식별 링크 확인 | 확인 |
| 과제 | `mod/assign/index.php`의 과제 식별 링크·마감·제출 상태 확인. 한 강좌의 실제 과제 1개를 두 번 조회해 동일 결과 확인 | 확인한 강좌 범위 |
| 퀴즈 | `mod/quiz/index.php`의 퀴즈 식별 링크·마감 2개를 두 번 조회해 동일 결과 확인. 점수로 제출 여부를 추정하지 않음 | 확인한 강좌 범위 |
| 캘린더 | 월간 화면의 일정 식별자와 일정 내보내기·iCal 메뉴 확인. 내보내기 실행·접근 키 조회는 하지 않음 | 메뉴 확인 |
| 온라인 강의 | `report/ubcompletion/user_progress.php`의 요구시간·학습시간·진도율과 일부 행의 원본 식별자·인정 기간 확인 | 부분 확인 |
| 정상 빈 응답 | 로그인 화면·예상 표 누락·추출 실패와 실제 빈 목록을 구분해야 함. 현재 실계정 표본으로 완전한 빈 결과는 검증하지 않음 | 미확인 |

별도 수집 도구는 브라우저 안에서 `fetch`로 위 목록·보고서만 읽고 필요한 필드만
추출했습니다. 인증 쿠키·토큰을 내보내지 않았고, 학교 비밀번호 입력이나 로그인
폼 제출은 자동화하지 않았습니다. 외부 브라우저의 인증 성공을 앱 WebView 인증
성공으로 간주하지 않습니다. 두 차례 동일 결과는 단기 재조회 증거이며 장시간
인증 유지·세션 만료 복구·변경 감지의 검증을 대신하지 않습니다.

진도표 표본에는 19개 행이 있었고, 이 중 활동 식별·기간 메타데이터가 있는 8개
행을 확인했습니다. 나머지에는 미학습 활동과 빈 주차 행이 섞여 있습니다. 이들을
모두 삭제된 강의로 취급하거나, 식별자가 없는 진도 행을 제목만으로 임의 연결하면
안 됩니다. 실제 활동과의 확실한 연결 기준을 더 검증해야 합니다.

퀴즈 링크는 상대 경로도 사용합니다. 목록 응답의 최종 URL을 기준으로 링크를
해석해야 하며, 링크 추출 실패로 0개가 된 것을 정상 빈 응답으로 처리하면 안 됩니다.
진도 보고서 상단의 연락처·학번 및 점수·접속 IP 등은 기능 수집 대상이 아닙니다.
실제 제품 추출 범위는 일정·제출 상태·진도 표의 필요한 셀로 제한합니다.

비식별 검증 결과: `work/issue65-cosmos/authenticated-read-verification.json`.
개인 과목명·학번·연락처·인증값은 저장소 문서나 테스트 fixture에 복사하지 않습니다.

일정·API 설정은 제공 여부만 확인하고 변경하지 않았습니다. 과제 제출, 퀴즈 시작,
강의 재생, 출석 인정 동작도 하지 않았습니다. 과제·퀴즈·동영상의 `view.php`
상세 화면은 조회만으로 학습 완료 상태가 바뀔 수 있어 열지 않았습니다. 일반
강좌 홈 조회에는 학교의 통상적인 접속 로그가 남을 수 있습니다.
[과제 상세의 완료 처리](https://github.com/moodle/moodle/blob/MOODLE_311_STABLE/mod/assign/view.php),
[퀴즈 상세의 완료 처리](https://github.com/moodle/moodle/blob/MOODLE_311_STABLE/mod/quiz/view.php).

특히 Moodle 3.11의 `user/managetoken.php`는 페이지를 여는 것만으로 토큰 생성
함수를 실행합니다. 상명 서버 구현이 같은지는 미확인입니다. 따라서 사용자
메뉴의 **보안키 링크 존재 여부만** 확인하며 페이지 진입·키 생성은 읽기 검증에
포함하지 않습니다. ICS URL에도 접근용 키가 포함될 수 있어 생성·가져오기 단계는
별도 범위를 확인합니다.
[공식 보안키 페이지 소스](https://github.com/moodle/moodle/blob/MOODLE_311_STABLE/user/managetoken.php),
[공식 캘린더 내보내기 소스](https://github.com/moodle/moodle/blob/MOODLE_311_STABLE/calendar/export.php).

## 구현 전 코드 조사와 후속 반영

- `CalendarEvent`의 `completed`는 사용자의 개인 완료 값입니다. LMS의 과제
  제출·강의 이수 상태와 같은 필드로 취급하지 않습니다.
- 조사 당시 이벤트 저장·Drive v2에는 LMS 원본 식별자와 제출·진도 메타데이터가
  없었습니다. 이후 별도 메타데이터와 소유권 검증을 SQLite·Drive·삭제 기록에
  추가했습니다. 메모나 일시적인 `readOnly` 플래그에 원본 상태를 숨기지 않습니다.
  저장 형식과 호환성 경계는 [LMS 메타데이터 명세](LMS_SYNC_METADATA.md)에 기록합니다.
- 기존 외부 캘린더 가져오기는 일회성 중복 건너뛰기 동작이며, 학사일정 동기화의
  빈 결과·사용자 수정 처리도 LMS 요구사항과 다릅니다. 해당 동작을 변경하지
  않고 별도 LMS 갱신 계층에서 서버 원본과 개인 메모·분류·알림을 분리합니다.
- 인증 토큰은 OS 보안 저장소를 사용하고 Drive·로그에 포함하지 않습니다.
  학교·계정 변경 중 도착하는 이전 응답이 새 계정에 반영되지 않도록 세션
  경계를 검증해야 합니다.
- 조사 당시 Drive는 LMS 소유자를 구분하지 않고 pending 일정·삭제 기록을
  수집했습니다. 이후 개인 일정의 기존 보존 동작을 유지하면서 LMS 업로드·표시·갱신과
  삭제 기록에 해당 소유자 경계를 추가했습니다. 구버전 앱에는 이 보호가 없으므로
  공유 스키마 릴리스는 네 플랫폼의 조정된 배포가 필요합니다.
- LMS 지원 대학 판정은 학사일정·시간표의 `AcademicProfile.supported`와
  분리했습니다. 학사 기능의 기존 판정은 이번 LMS 대상이 아닌 단국대도 포함합니다.
  LMS 연결은 저장된 학사 프로필을 사용하며 현재 상명대학교부터 검증합니다.

공개 조사·개발용 브라우저 검증 당시에는 제품 코드·DB 스키마·설치 앱을 변경하지
않았습니다. 이후 승인된 구현과 테스트 앱 업데이트가 진행되었으므로 그 당시의
미변경 기록을 현재 상태로 해석하지 않습니다. Mac 앱의 실제 자동 가져오기 결과는
상단 현재 상태에 별도로 기록했으며, 다른 학교·플랫폼의 지원이나 공개 릴리스를
의미하지 않습니다. 앱에서 사용하는 구체안과 남은 검증은
[웹 세션 구현안](ISSUE_65_COSMOS_WEB_SESSION_PLAN.md)에 정리했습니다.
