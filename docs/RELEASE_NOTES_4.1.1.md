# DailyCalendar 4.1.1

4.1.0에서 나온 동기화 속도 문제와 일정 화면 문제를 고친 긴급 패치입니다.

## 바뀐 점

- Google Drive 동기화가 빨라졌습니다.
  - 일정 파일을 여러 개 동시에 주고받습니다.
  - 내용이 같은 파일은 다시 내려받지 않습니다.
  - 동기화 전에 늘 3초씩 기다리던 대기를 없앴습니다.
  - 요청 한도에 걸리면 잠시 기다렸다가 다시 시도합니다.
- 동기화하는 동안 캘린더가 깜빡이거나 보던 위치가 잠깐 옮겨 가던 문제를 고쳤습니다.
- 동기화 배너가 나타나고 사라질 때 화면 전체가 위아래로 튀던 문제를 고쳤습니다.
- 일정 알람을 여러 시각에 울리게 고를 수 있습니다. 예를 들어 30분 전, 10분 전, 정시에 모두 울리게 할 수 있습니다.
- 자정을 넘기는 일정을 다음 날에도 표시할지 일정마다 정할 수 있습니다.
- 하루 일정 시트를 고쳤습니다.
  - 아래로 끌어서 닫는 기준을 완화했습니다.
  - 빠르게 튕겨 내려도 닫히지 않던 문제를 고쳤습니다.
  - 좌우로 날짜를 넘기면 넘긴 방향에서 새 날짜가 밀려 들어오고, 로딩 표시가 깜빡이지 않습니다.
- 요일을 지정한 주간 반복(예: 격주 월·금)을 시작일의 요일부터 셉니다. 반복 일정을 며칠 옮기거나 중간 회차부터 나눠도 모든 회차의 간격이 같게 유지됩니다.
- 좁은 화면에서 주간 날짜 패널 머리글이 넘치던 문제를 고쳤습니다.
- 일정 추가·수정 팝업의 하단 버튼(템플릿으로 저장·취소·저장)을 한 줄에 놓았습니다. 이제 휴대폰에서 버튼이 세로로 쌓이지 않습니다.
- 시간표 자산에서 불필요한 공백을 지워 앱 용량을 줄였습니다. 시간표 내용은 그대로입니다.
- 분석 수신기가 새 속성이 든 배치를 거부해도 같은 배치의 다른 이벤트는 잃지 않습니다. 앱은 거부된 배치를 반으로 나눠 다시 보내고, 하나만 남은 이벤트가 또 거부되면 그 이벤트만 버립니다.

## 같은 계정의 모든 기기를 업데이트해 주세요

이 버전은 Google Drive 일정 파일에 새 값을 씁니다. 같은 Google 계정으로 동기화하는 기기는 모두 4.1.1로 업데이트해 주세요. 4.1.0 이하 기기(아래 구버전 기기)를 함께 쓰면 아래처럼 동작합니다.

- 알람 시각을 여러 개 고른 일정은 구버전 기기에서 가장 이른 알람 하나만 울립니다.
  - 구버전 기기에서 제목처럼 알람이 아닌 내용만 고쳐 저장하면, 신버전 기기가 그 파일을 받을 때 갖고 있던 여러 알람 목록을 되살려 다시 올립니다.
  - 구버전 기기에서 대표 알람을 바꾸거나 알람을 끄면 알람이 하나만 남습니다.
  - 여러 알람 목록을 가진 신버전 기기가 하나도 없으면(앱 재설치 등) 목록을 되살리지 못합니다.
- 템플릿도 같은 규칙을 따릅니다.
  - 구버전 기기에서 이름이나 즐겨찾기만 바꾸면 신버전 기기가 여러 알람과 다음 날 표시 끔을 되살립니다.
  - 구버전 기기에서 내용을 고치면 알람이 하나만 남습니다.
  - 이 버전 전에 구버전 기기 때문에 이미 값을 잃은 템플릿은 되살리지 못합니다.
- 다음 날 표시를 끈 일정은 구버전 기기가 이 값을 읽지 못해 기기 전체 설정을 따릅니다.
- 구버전 기기는 요일을 지정한 주간 반복을 월요일부터 셉니다.
  - 시작일이 월요일이 아니거나 반복을 옮기거나 나눈 일정은 구버전 기기에서 일부 회차가 1주 어긋나 보일 수 있습니다.
  - 구버전 기기에서 나눈 일정을 고쳐 저장하면 `weekStart`가 지워집니다. 신버전 기기는 나눌 때 제외 날짜에 함께 남긴 표식으로 원래 주 경계를 다시 찾습니다.

어느 경우에도 일정 자체는 지워지지 않습니다. Windows 앱은 자동으로 업데이트합니다. Android, macOS, iPhone·iPad는 기기마다 직접 업데이트해 주세요.

## 함께 게시하는 산출물

Drive v2 일정·템플릿 파일 형식이 바뀌어 Windows·Android 산출물과 Mac·iPhone 산출물을 함께 게시합니다. Linux APT 저장소는 이번 게시에서 갱신하지 않았습니다. 기존 4.1.1-1 패키지(`bca1ff795` 빌드)를 그대로 제공합니다.

## 동기화·저장 형식 변경

- 로컬 DB 스키마를 12에서 15로 올립니다. 앱을 처음 실행할 때 기존 데이터를 새 스키마로 옮깁니다.
  - 13: 여러 알람 시각
  - 14: 내용이 같은 Drive 파일을 다시 받지 않으려고 기기 안에 두는 사본(Drive에 올리지 않음)
  - 15: 일정별 다음 날 표시
- Drive v2 일정 파일(`daily-sync-v2-event-{eventId}.json`)
  - 알람 시각이 2개 이상일 때만 `alarmMinutesBeforeList`·`alarmCustomAtList`를 씁니다. 기존 `alarmMinutesBefore`·`alarmCustomAt`에는 계속 대표 알람을 씁니다.
  - `showOvernightOnFollowingDays`를 씁니다.
  - 반복 일정을 원래 시작 요일이 아닌 회차부터 나누면 `recurrenceDetails` 안에 `weekStart`를 씁니다.
  - 같은 경우 새 시작일이 속한 주의 첫날(시작일보다 1~6일 앞)을 `recurrenceExcludedDates`에도 넣습니다. 신버전은 `weekStart`가 없으면 이 날짜의 요일을 주 시작으로 읽습니다. 이 표식에는 새 키를 쓰지 않습니다.
- 템플릿 파일(`daily-sync-v2-templates.json`)
  - 여러 알람 시각과 다음 날 표시 끔을 저장합니다.
  - `templateFull/<id>` 사본을 추가합니다. 신버전은 템플릿을 저장할 때 `template/<id>`와 같은 값을 사본에도 쓰고, 지울 때는 둘 다 지웁니다.
  - 구버전은 `template/` 키만 읽고, 병합할 때 사본을 그대로 둡니다.
  - `schemaVersion`은 바꾸지 않았습니다. 템플릿 파일 크기는 약 2배가 됩니다.
- 설정 동기화 문서의 전역 다음 날 표시 값(`calendarShowOvernightEventsOnFollowingDays`)은 이 버전부터 읽지도 쓰지도 않습니다. 구버전 기기가 올린 값은 그대로 남겨 둡니다.

## 알려진 제한

- Mac App Store용 4.1.1은 4.1.0과 마찬가지로 Apple Silicon(M 시리즈) Mac에서만 실행됩니다.
- 구버전과 신버전 기기를 함께 쓸 때의 동작은 코드를 정적으로 확인하고 자동 테스트로 검증했습니다. 실제 Google Drive에서 여러 기기를 함께 써 보지는 않았습니다.
- Drive 동시 전송을 6개로 했을 때 실제 계정에서 요청 한도 응답이 얼마나 자주 오는지는 측정하지 않았습니다.

## 검증

- 4.1.1 코드를 모두 담은 main `1246856ac`에서 CI(Platform Builds, 실행 42558896393) 작업 7개가 모두 통과했습니다. 작업은 Dart 분석·전체 테스트, 시간표 테스트 3개, Android·Windows Debug 빌드, Apple LMS 세션 테스트입니다. 그 뒤 main에는 이 릴리스 노트와 README 수정만 추가했습니다.
- macOS, iPhone 시뮬레이터, Android 에뮬레이터의 테스트 앱을 업데이트한 뒤 데이터 보존, Drive 동기화, 여러 알람(Android 시스템 알람 예약·취소), 일정별 다음 날 표시, 하루 시트 날짜 이동을 확인했습니다.
- 그 테스트에서 찾은 문제 3건(#803~#805)을 고쳐 이 버전에 넣었습니다. 고친 뒤의 실제 기기 동작은 확인하지 않았습니다.
- 4.1.1 첫 게시 뒤 넣은 수정 두 가지는 자동 테스트로만 확인했고, 실제 4.1.0 기기와 운영 Google Drive로 함께 써 보지 않았습니다. 하나는 구버전 기기와 함께 쓸 때 여러 알람·다음 날 표시·격주 주 경계를 보존하는 수정이고, 다른 하나는 분석 이벤트 손실 방지입니다.
