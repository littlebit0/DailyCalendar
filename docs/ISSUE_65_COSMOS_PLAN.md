# 이슈 65 코스모스 연동 계획 — 승인됨, 상명대 경로 검증 중

2026-09-26 기준. [이슈 65](https://github.com/littlebit0/DailyCalendar/issues/65)의
개인 과제·온라인 강의·시험 일정 연동을 **코스모스 계열만** 대상으로 검토합니다.
사용자가 2026-09-26 이 진행안을 승인했습니다. 현재는 첫 단계인 상명대 인증·조회
경로 검증 중입니다. 사용자는 로그인 후 읽기 전용 확인도 허용했습니다.
실제 학교 인증은 사용자가 공식 화면에서 직접 진행합니다. 앱의 연결·자동 동기화
구현은 인증 반환과 데이터 접근 경로를 검증한 뒤 진행합니다.
공개 응답과 확인 범위는 [검증 기록](ISSUE_65_COSMOS_FEASIBILITY.md)에 기록합니다.

## 제안 범위와 순서

1. **상명대 인증·조회 경로 검증**: Daily에서 사용할 수 있는 인증 방식과 실제
   읽기 데이터 범위를 먼저 확인합니다. 학교가 허용하는 API·사용자별 토큰·공식
   SSO 반환 경로를 우선 확인하고, 실제 로그인이 필요할 때 조회 범위를 별도로
   안내해 승인을 받습니다. 사용자가 학교의 공식 화면에서 직접 인증합니다.
2. **검증된 항목부터 구현**: 과제 마감·제출 상태 → 온라인 강의 수강기간·출석/진도
   → 퀴즈/시험 → LMS 일정·활동 완료 순서입니다. 제공되지 않는 상태는 추측하거나
   가짜 완료 값으로 채우지 않습니다. 확인된 항목·접근 방식을 제시한 뒤 구현 범위를 확정합니다.
3. **전남대 확장**: 공통 코스모스 처리에 학교별 주소·인증 설정을 연결하고 실제
   응답 차이를 검증합니다. 상명과 전남의 캠퍼스는 등록된 통합 학교 기준입니다.
4. **플랫폼 검증**: 승인된 실계정에서 중복 방지·마감 수정·제출 상태·인증 만료·
   정상 빈 결과·실패 시 복구를 확인합니다. 테스트 앱 업데이트와 실제 계정 검증은
   구분하여 기록합니다. 네이티브 인증 설정 변경이 필요하면 별도 변경안을 제시합니다.

상명과 전남은 공식 안내에 코스모스 사용이 명시되어 있습니다.
[상명 안내](https://ecampus.smu.ac.kr/mod/ubboard/article.php?bwid=98878&id=3),
[전남 안내](https://sel.jnu.ac.kr/mod/ubboard/article.php?bwid=745057&id=1).
단국대 LMS는 Canvas/LearningX이므로 이번 LMS 지원 대상에는 포함하지 않습니다.
기존 단국대 학사일정·시간표 지원은 유지합니다.
[단국대 2026-2 안내](https://iacf.dankook.ac.kr/web/kor/-390?_dku_bbs_web_BbsPortlet_action=view_message&_dku_bbs_web_BbsPortlet_bbsMessageId=180702&p_p_id=dku_bbs_web_BbsPortlet&p_p_lifecycle=0&redirect=%2Fweb%2Fkor).

## 화면 제안

- 설정의 학사정보에서 **LMS 연결**로 진입합니다. 등록한 대학의 LMS를 사용합니다.
- 사용자는 앱에서 학교 공식 SSO 인증을 시작하고 인증이 끝나면 앱으로 돌아옵니다.
  연결된 세션으로 이후 조회를 자동 수행하며, 토큰 복사·수동 파일 가져오기를
  일상 사용 절차로 요구하지 않습니다. 외부 브라우저는 현재의 개발 검증 절차입니다.
  인증 만료로 다시 사용자 인증이 필요한 경우에만 재로그인을 안내합니다.
- 연결 화면: 학교 계정 연결, 지원 항목, 마지막 확인 시각, 지금 동기화, 연결 해제.
- 개인 캘린더에서 마감·수강기간을 표시하고, 상세에서 제출·진도와 원문 열기를 제공합니다.
- 최신 조회 실패 시 마지막 정상 자료의 확인 시각과 재로그인 필요 여부를 표시합니다.

새 진입점과 상세 상태 표시는 위 구현안의 승인 범위입니다. 이 밖의 디자인 변경은
별도로 제안합니다. 현재 진행 중인 상단 바·시간표 전환 수정과는 분리된 작업입니다.

## 인증과 데이터 기준

- Google 학사정보로 대학을 찾되, 학교 LMS 인증은 따로 처리합니다.
- 학교 비밀번호를 장기 저장하지 않습니다. 필요한 토큰·세션은 OS 보안 저장소에
  보관하고 연결 해제 시 삭제합니다. 인증자료는 Drive나 로그로 보내지 않습니다.
- 공식/표준 읽기 API, 허용된 구조화 API, ICS 순으로 실제 제공 범위를 확인합니다.
  ICS만으로 제출·출석·진도를 제공한다고 간주하지 않습니다.
- 코스모스가 Moodle 기반이라는 사실만으로 외부 앱의 API 접근을 보장할 수 없습니다.
  학교 로그인 창을 열었다는 사실만으로 Daily가 세션을 받을 수도 없습니다.
  공개 자료에서 Daily용 토큰·콜백 허용 여부는 확인되지 않았습니다.
  [코스모스 공식 설명](https://www.coursemos.kr/ko/lxp/lms),
  [Moodle 서비스·권한 설정](https://docs.moodle.org/501/en/Using_web_services).
- HTML 파싱이나 다른 인증 접근이 필요하면 실제 근거와 변경안을 다시 제시합니다.
  로그인·2차 인증·서버의 접근 제한을 우회하지 않습니다.

## 갱신·저장 제안

- LMS 제목·기간·제출·진도는 서버에서 받은 값을 기준으로 유지합니다.
  개인 메모·분류·알림은 별도로 보존합니다.
- 학교·계정·원본 항목 ID로 중복을 방지하고, 한 항목의 수정은 같은 항목에 반영합니다.
- 완전한 정상 응답에서만 항목 제거를 판단합니다. 정상 빈 목록은 최신 ‘항목 없음’이며,
  실패·부분 응답을 빈 목록으로 처리하지 않습니다.
- 서버 조회 실패 시에만 마지막 정상 자료를 표시하고 확인 시각을 함께 보여 줍니다.
  인증 만료는 가능한 갱신·재조회 후 재로그인 안내로 구분합니다.
- 앱 시작·복귀·사용자 새로고침을 순차 요청과 간격 제한으로 처리합니다.
  실시간 push와 정기 백그라운드 갱신은 실제 지원 여부 확인 후 제안합니다.
- 가져온 일정과 개인 보조정보는 기존 Google Drive 동기화를 사용합니다.
  LMS의 원본 응답 전체를 Drive에 보관하는 방식은 이 승인안에 포함하지 않습니다.
  장애 시 표시할 최소 정상 자료는 계정별 캐시로 분리하며 기본 원본으로 사용하지 않습니다.

## 코드 구조와 승인 경계

학교 설정 / 인증 / 데이터 조회 / 정규화 / 캘린더 반영을 나눕니다. 기존 학사일정
서비스는 빈 결과와 사용자 수정 처리 기준이 달라 LMS 전용 계층이 필요합니다.
기존 일정 저장·보안 저장소·요청 큐의 검증된 부분을 재사용합니다.

진행안은 승인되었고, 현재 확인한 것은 공개 근거와 기존 코드 구조입니다. 학교별
실제 API 필드·로그인 반환 경로·진도 권한은 미확정입니다. **로그인 후 수강 목록·과제 마감/제출 상태·퀴즈 일정·연동 메뉴의
읽기 전용 확인은 허용되었습니다.** 키 생성·설정 변경·제출·수강 등 쓰기 동작은
이 허용에 포함하지 않습니다. 검증된 접근 경로 없이
지원 가능하다고 표시하거나 동작하지 않는 연결 화면을 추가하지 않습니다.
